# Conductor

`Conductor` は、[ZMK Firmware](https://zmk.dev/) をベースにしたカスタムキーボードファームウェア設定です。

## 主な構成

- **ボード**: `seeeduino_xiao_ble`
- **シールド**: 
  - `monokey_R` + `rgbled_adapter`
  - `monokey_L` + `rgbled_adapter`
  - `settings_reset`

## Mac / Windows配列の切替

- `changewin`: **U＋Oを約0.5秒保持**するとWindows用レイヤーへ切り替わります。
- `tomac`: **I＋Oを約0.5秒保持**するとMac用レイヤーへ戻ります。

各組み合わせは50ms以内に押し始め、両方を押したまま保持してください。ZMK v0.3では最初のキーを押した時点から500msを数えます。判定前に片方でも離すと切替を取り消します。途中で別のキーを押しても判定時間は短縮されません。判定中の別キー入力は、片方を離すか500msが経過するまで一時保留されます。切替後はキーを離しても選んだ配列を維持します。どのレイヤーからも操作できます。

短い同時押しでcomboが成立した場合、レイヤーは切り替わりませんが、そのU/OまたはI/Oは文字として出力されません。通常の文字入力は、各キーを離してから次を押すか、押し始めの間隔が50ms以上ならそのまま通ります。

## Windowsでの親指シフト入力

Windows用レイヤーでは、左の言語キー（位置34）は無変換を送ります。右の言語キー（位置37）は`LANG1`（IMEオン）を送ってから下記のNICOLAレイヤーへ入ります。NICOLAレイヤーを使う場合、やまぶきRなどOS側の親指シフトソフトは不要です（IMEはローマ字入力モードにします）。単独の変換キーが必要なら`config/monokey.keymap`の`kana_win`マクロを変更してください。

左の言語キーとSpace（位置34＋35）の同時押しで英数を送る`lang2` comboは、Macの通常レイヤー（0）が最上位のときだけ有効です。Windowsで無変換とSpaceの押下が重なっても、このcomboによるIMEオフは送られません。Macでも追加レイヤーを使用中はこのcomboが無効になります。Spaceの短押し／長押しレイヤー切替の設定は従来どおりです。

`LANGUAGE_2`はWindowsでIMEオフに対応するため、この制限で親指入力と英数切替の競合を避けます（[Microsoftのキー仕様](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/keyboard-japan-ime)）。入力ソフトやIME側の単押し設定による切替は別途設定を確認してください。

## 親指シフト（NICOLA）モード

OS側の親指シフトソフト（Lacaille、やまぶきR）を使わず、キーボード内で同時打鍵を判定し、IMEへはローマ字のキー列（例: か → `k` `a`）を送ります。IMEはローマ字入力モードにしておきます。エンジンは`modules/nicola/`にあり、取込元と変更点は同ディレクトリの`VENDORED.md`と`CHANGES.md`に記録しています。

- **入る**: かなキー（位置37）を押す。`LANG1`を送ってからNICOLAレイヤーへ入ります（Macはレイヤー2、Windowsはレイヤー3）。右手側LEDはシアンになります。
- **文字キー**: 位置0〜29の30キーがNICOLA配列（`&nc`）。親指キーは左＝位置34（英数キー、`&ncl`）、右＝位置37（かなキー、`&ncr`）。
- **左親指の単独タップ**: `LANG2`（英数）を送ってNICOLAレイヤーを抜けます。ただし、かなを送ってからEnter／Escを押すまでは「IMEに未確定文字が残っている」と推定して抑止します。意図的に抜けたいときは1秒以内にもう一度タップします（`guard-repeat-ms`）。送ったかなの数を数えていて、Backspace／Deleteで1つずつ減らし、0になれば抑止を解除します（変換中の最初のBackspaceは取消として数えません。Cmd／Option付きのBackspaceと0.5秒以上の長押しは全消しとみなします。`guard-bs-hold-ms`）。最後のキー押下から3秒以上操作がなければ未確定文字は消えたとみなし、抑止しません（`guard-timeout-ms`、マウスでの確定やアプリ切替のように、キーボードから見えない確定への備え）。
- **右親指の単独タップ**: `LANG1`（かな）を送ります。レイヤーは維持します。
- **判定**: ms方式、同時打鍵窓70ms、連続シフトあり。親指を先に押して遅れて文字を打った場合は窓に関係なくシフトします。設定は`config/monokey.keymap`の`&nc { ... }`です。
- **修飾キー**: Shift／Ctrl／Alt／Cmdを押している間は素のキーを送ります。Space／Tab／Backspaceの長押しレイヤーは従来どおり使えます。
- **無効になるcombo**: NICOLAレイヤーでは文字キー同士のcombo（K+Lスクロール、L+;中クリック、Z+X・.+/のCtrl、V+BのWin、U+O・I+OのOS切替、Tab+かな）を無効にしています。使うときは英数で基本レイヤーへ戻ってください。
- **小書きかな**: ぁぃぅぇぉ・ゃゅょ・っは`x`接頭（xa、xya、xtu など）で送ります。macOSの日本語IMが`l`接頭を受け付けないためです。
- **未割当**: @キーの゛面など、ローマ字で表現できない面は未割当です。

レイヤー番号を変更しました（FUNCTION以降が2つ後ろへ）。`monokey_R.overlay`の自動マウスレイヤー（8）とスクロールレイヤー（9）、`monokey_R.conf`のLED色も追従済みです。ZMK Studioで保存した配列は旧番号のまま残るため、新ファームウェアの書込後にZMK Studioの「Restore stock settings」で初期化してから使ってください（Bluetoothのペアリングは消えません）。

## 依存とビルド環境の更新

`config/west.yml`のZMK、Zephyr、追加moduleは、成功済みの[run 35062608057](https://github.com/gunsturn/conductor/actions/runs/35062608057)を基準にcommit SHAへ固定しています。Zephyrのimportは上流と同じ除外リストを維持しています。

CIは`.github/workflows/build-pinned.yml`を使います。ZMK v0.3のworkflowを基に、Actionsを完全なcommit SHA、ビルドコンテナをSHA-256 digestへ固定しました。tokenは`contents: read`のみ、checkout後には認証情報を残しません。westソースの共有キャッシュ復元は行わず、各runで`west manifest --freeze --active-only`をログへ出します。GitHub-hosted runner自体のイメージは固定対象外です。

2026-10-03に同じcontainer digestのarm64環境で、現在の右・左・settings_resetの3ビルドとUF2生成を確認しました。GitHub Actionsのartifact upload/mergeと実機書込みは、このローカル検証には含みません。

更新時は、依存とコンテナの一次情報・アドバイザリを確認し、上流workflowとの差分をレビューしてください。右（Studio有効）・左・settings_resetの3buildとartifact結合を確認してから採用します。firmwareの実機書込みは別操作です。
